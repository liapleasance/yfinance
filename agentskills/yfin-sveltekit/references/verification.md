# Verification ladder - what each check proves

All three run inside `verify_all.sh`; the last line of `VERIFY_SUMMARY.txt` is OVERALL PASS|FAIL.

1. **verify_pair** (final vs ORIGINAL): every file parses; import/export specifiers are identical; no string literal of the original is missing. Catches lost code/strings and interface changes.
2. **ast_equiv** (final vs *base*): AST identical except names of bound variables. *base* = the Wakaru output for normal files and the ORIGINAL for fallback files (`make_base.sh`). Proves stage 2 (renames, annotations, prettier) did not change structure and no reference was re-bound (rename capture). Normalisations tolerated: comments, quote style, `export` inline vs separate, `&&`/`||` re-association, braces on if/else, JSX whitespace, numeric object keys, regex flag order, empty statements. It does NOT prove Wakaru itself is faithful.
3. **runtime_cmp** (final vs ORIGINAL): headless Chromium, network blocked, Math.random / Date / performance.now fixed, 5 s import timeout, a fresh browser context per module (calls can leave global state behind). Every module is imported in both trees and compared on: outcome (ok/error message), export shapes, DOM of Svelte components rendered with empty props, and **differential calls**: every exported plain function (not classes/components, up to 300 per module) is CALLED with a fixed battery of 19 argument vectors (none, undefined, 0, 1, -1, strings, null, arrays, objects, two-arg and three-arg vectors, a timestamp) and the return value / thrown error class / promise state is compared. This is what catches Wakaru semantic breakage, including changes that do not show at load time (verified in the selftest with a planted `+` -> `-`).
   Noise control: error MESSAGES and non-native class names are not compared (renames change them); a call still pending in one tree and settled in the other is a timing difference, not a diff; the ORIGINAL is run twice and functions whose results differ between the two runs (nondeterministic) are ignored and counted; a module whose call phase hits a harness error (e.g. navigation) falls back to load-time comparison and is counted. On a known-good real tree (1086 modules, ~1600 functions called) it reported 0 differences, 3 nondeterministic functions ignored. `YFIN_FUZZ=0` turns the calls off (about 10 times faster). `YFIN_FUZZ_ISOLATE=1` gives each exported function's battery its own fresh page instead of sharing one page per module: a call that mutates shared module state can no longer contaminate the next call's results — at the cost of one browser context per function (opt-in; the orig2 self-baseline already filters order-dependent effects in the default mode).
   Limits: calls use synthetic arguments, so deep branches that need real data are not reached; functions that only register callbacks, install methods on another object (e.g. chart studies) or return closures are called but their inner behaviour is not exercised; no interaction, no network; if both trees fail identically it passes.

Guarding the guards: `selftest.sh` plants bugs (wrong binding, lost string, added global, removed export, class conversion, JSX, a semantic change visible only when called) and requires the exact expected failure. Mutation-tested: sabotaging ast_equiv, verify_pair, runtime_cmp or scan_hazards makes the selftest fail. Run it before every real verification.

Report numbers, not adjectives. Never write "100%".
